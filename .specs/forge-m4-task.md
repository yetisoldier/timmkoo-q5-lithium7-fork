Implement Bob's M4 board-port design. The fork kernel PANICS (reset-loop ~5 s) on the Q5; the
root cause is the display/LCM selection path (LK passes `gc9503v_wvga_dsi_vdo_hsd|boe`, the a106
kernel list is `hx8369b*`, so the probe walks the miss path with `lcm_drv==NULL` → fault). D18
already repaired the list; you are adding the robustness guard + the Q5 board-value port.

**Full design + every blob anchor + exact initcall refs: `.specs/bob-m4-board-port.md`. Read it
first. Nothing below is invented; every constant cites a blob anchor you must re-verify, not copy

### 2. D20 — Q5 board-value port (with the include-precedence mechanism)
The trap (read §3.2 carefully): **DCT headers are regenerated by `DrvGen` from `q5/dct/dct/codegen.dws`
into the O-dir at every build** — editing `q5/dct/dct/inc/*.h` in the source tree is a silent no-op.
Chosen mechanism: add `-I$(MTK_PROJECT_PATH_ROOT)/dct/dct/inc` BEFORE the `-I$(DRVGEN_OUT)/inc`
line in `drivers/misc/mediatek/Makefile.custom`, and maintain the Q5-pinned values in the source
headers. Override only the headers that carry changed values.

Port (priority order, each with its blob anchor in §3.2/§2 — re-verify each):
1. MSDC1 card-detect: `cust_eint.h` + `cust_gpio_usage.h` → GPIO3 (a106: EINT8/GPIO8). Complete the
   EINT channel/trigger decode from the `mt_eint_registration` args near `msdc_enable_cd_irq`.
2. ACCDET: → GPIO4 (a106: ch0/GPIO0), plus channel+flag from the adjacent registration.
3. OTG: `GPIO_OTG_IDDIG_EINT_PIN`/`GPIO_OTG_DRVVBUS_PIN` (a106 GPIO17/21) from `mt_usb_otg_init`
   pool-decode (rodata struct near `0xc0daf358`).
4. Leds hygiene: `q5/leds/mt65xx/cust_leds.c` — red/green/blue/jogball/keyboard/button →
   `MT65XX_LED_MODE_NONE, -1` (keep `lcd-backlight` BLS entry byte-identical).
5. Keypad: decode the blob `{114,115}` keymap + pwrkey flag; port ONLY if divergent (expected match).
6. RTC BBPU pin + vibrator cust struct — hygiene if divergent.
7. Camera power/reset: assertion-only re-check vs `kdCISModulePowerOn @0xc004deac`.
